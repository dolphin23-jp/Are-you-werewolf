# アプローチ再設定（2026-10）: 「コードが決め、LLMが言葉にする」から「コードが事実と論理を保証し、LLMが考えて話す」へ

## この文書の位置づけ

目標は変わっていない。**人間1人 + AI16人の17人村で、かつて人間同士で遊んだチャット人狼と
同じ体験ができること**である。AIの発言と思考が、少なくとも人間のプレイヤーに「見える」
水準に達する必要がある。

変えるのは、そこへ至る経路である。この文書は、現在の経路のどこが律速になっているかを
実測で示し、経路を切り替える判断と、切り替え後の完成条件を定める。

`docs/architecture.md`（v2の設計）、`docs/self-play-training.md`（自己対戦RL）、
`docs/real_game_log_reasoning_plan.md`（実ログ基盤）はいずれも有効な記録として残すが、
**優先順位についてはこの文書が優先する**。

---

## 1. 結論（先に書く）

1. 律速段階は「推理の精度」でも「学習の計算量」でもなく、**設計の置き場所**である。
   v2はLLMから「考えること」を取り上げ、言い回しだけを残した。結果、卓は正しいが
   人間に見えない。同時に、人間らしさを本来担うはずのLLM呼び出し自体が、推論モデル
   向けに調整されておらず半数が失敗している。
2. **自己対戦RL（Transformer/PSRO）と実ログ学習パイプラインは、完成への最短経路から
   外す**。コードは残すが、これ以上の投資をしない。
3. 新しい経路 **v3** を入れる: コードは事実台帳・論理ソルバー・検証・発言順・公開義務
   （結果を出す、COする）だけを担保し、**誰を疑うか・投票・夜行動・発言内容はLLMが
   「盤面メモ」を読んで決める**。発言はチャット調で、定型文は挿入しない。
4. 完成条件を「人間らしさ」の実測指標で定義し、v3 をその指標で評価してから既定にする。

## 2. 現状診断

### 2.1 実測: gpt-5.6-luna によるv2のライブ対戦（seed 11、5日で村勝利）

`backend/artifacts/live-ab-postfix/11-v2-transcript.json` から。

> **この表は gpt-5.6-luna の値である。** 既定モデルは gpt-6.0-luna に切り替わった
> （性能向上・コスト低下）。表の行は二種類に分かれる。
>
> - **モデル側の性質**（成功率、strict schema の可否、推論トークン比率、レイテンシ、
>   待ち時間）: gpt-6.0-luna では変わりうる。**Phase B の最初に同じ条件で取り直し、
>   これを v2 / v3 の比較の基準線にする**。この行だけを根拠に「半数が失敗」と
>   結論しない。
> - **コード側の性質**（定型句の注入、`(pN)` 表記、発言数の上限、共有者の対抗扱い、
>   狼チャットと襲撃の分断）: モデルを替えても変わらない。v3 の必要性はこちらで立つ。

| 指標 | 値 |
|---|---|
| LLM呼び出し | 112回（HTTP 114） |
| 成功率 | **49.1%**（失敗57件はすべて `finish_reason=length` の途中切れ） |
| strict JSON schema | 0件（エンドポイントが拒否、以後 `json_object` のみ） |
| 推論トークン | 91,721 = **completion の 69.5%** |
| 1呼び出しの平均プロンプト | 約5,300トークン |
| レイテンシ | 平均12.4秒 / p95 17.2秒 / 最大28.0秒 |
| 公開発言1件あたりの待ち時間 | **28.1秒** |
| 1日あたりの公開発言 | **約10件**（5日で50件） |
| 試合の実時間 | 23分（うちLLM待ち 23分） |
| 定型句「現時点の第一処刑候補は〜です。」を含む公開発言 | **50件中49件** |
| 「名前(pN)」表記を含む公開発言 | 50件中50件 |

るる鯖の17A村は、1日に数十〜数百の短い発言が飛び交う。いまの卓は、28秒に1回、
全員が同じ書き出しで同じ構造の段落を読み上げる。これは人間のプレイヤーには見えない。

### 2.2 同じ対戦で起きていた推理の破綻

- **共有者2人CO = 「対抗」扱い**。`BeliefEngine._contests` は「同じ役職のCOが2人以上」を
  対抗と判定していた。共有者は定員2なので2人COは正常な形だが、村人4席が4日間
  「共有COが2人いて少なくとも1人は偽」と繰り返し、**2日目に真の共有者(p3)が処刑された**。
  人間は絶対にしない誤りである。本PRで修正した（`ROLE_DEFINITIONS[role].count` を超えた
  場合だけ対抗）。
- **狼チャットと襲撃の分断**。狼は1日目・2日目の夜に「p8（真占い）即噛み」と相談したが、
  襲撃先はコードが信念エンジンから別に決めるため、p8は最終日まで生存した。
  v2では「2つの推論系が並走する」ことを発言と投票については潰したが、夜については残っていた。
- **騙り計画の不発**。偽霊媒を割り当てられた狂人(p7)は5日間で一度も公開発言せず、
  騙りCOもしなかった。必須発言者の仕組みは「結果を持つ席」「CO予定の席」を拾うが、
  席が選ばれても生成が途中切れすれば何も起きない。

### 2.3 3本の線路がそれぞれ止まっている理由

**(a) v2「コードが決め、LLMが言葉にする」**

- 発言の中身（結論・根拠・確度・第二候補・反対材料）は固定文言のブリーフとして渡され、
  モデルは「上の結論・根拠・数値は変更しないでください」と指示される。16席が同じ
  ブリーフ構造を復唱するため、`docs/architecture.md` が警戒した「17個の帽子をかぶった
  1人」が、今度はブリーフ自身によって再現されている。
- 推理の深さは信念エンジンの証拠カテゴリ8種（公開黒・白・対抗・確定済み席への投票・
  多数派圧・告発・誤引用）で頭打ちになる。人間の17A推理（内訳、囲い、身内切り、
  占い先指定、狐ケア、縄計算からの吊り順）はここにない。足すには1カテゴリごとに
  コードと重みを書く必要があり、それが進まないことが律速になっている。
- v2 の最大の成果（事実台帳・z3ソルバー・検証・監査・公開情報境界）は、
  「モデルに決めさせない」こととは独立に価値がある。これは残す。

**(b) 自己対戦RL（`backend/app/training/`、約11,500行、直近50PRのうち38本）**

- 学習対象は構造化された意味行動（CO/判定/投票/夜行動の離散選択）であり、
  自然言語は入っていない。「人間の発言→意味解析」「学習済み行動→LLMで文章化」は
  いずれも未着手（`docs/self-play-training.md` の Next stages 5, 9）。
- 報酬は終端の勝敗のみ（+1/-1/0）、17人の隠匿情報ゲームで、パイロットは数千試合。
  同文書自身が「10万試合以上で初めて評価に値する」と書いている。1人の開発者が
  GPUを借りて回す規模ではない。
- 仮に強い方策が得られても、**自己対戦で収束した慣習が人間の慣習と一致する保証はない**
  （公開で「人狼」とCOする、初日に全員黙る、など）。目標は「強い」ではなく
  「かつての人間のように見える」である。
- したがってこの線路は、目標に対して**遠回りかつ到達保証がない**。研究資産としては
  残し、完成の critical path から外す。

**(c) 実ログ学習パイプライン（るる鯖17Aの training-ready ゲート）**

- 2試合をケーススタディ、8カットオフを専門家注釈。しかし元HTMLの取得・公開版/完全版の
  整列・正規イベント化は未完で、`CLAUDE.md` の規約どおり1試合も training-ready に達して
  いない。ゲートの設計は正しいが、**重み学習の前提としては完成が遠い**。
- 一方で、ケーススタディに書かれた教訓（「最も狼らしい人」と「今日吊るべき人」は別、
  噛まれた占い候補が真とは限らない、死んだ真候補視点のグレーは「安全」ではない、
  能力対象は負け筋に従う）は、**そのまま日本語でLLMに渡せる知識**である。
  学習データではなく、プロンプトのドクトリンとして即座に使える。

### 2.4 律速段階の正体

「人間らしい発言と思考」を得るための手段として、**(a)はLLMから思考を取り上げ、
(b)はLLMを使わず、(c)はLLMを使う前にデータ基盤の完成を待っている**。
三つとも、2026年のLLMが最も得意な「構造化された事実をもとに、人格を持って日本語で
推理し、話す」ことを、設計上使っていない。これが律速である。

## 3. 方針転換の原則

> **コードは「何が事実か」「何が論理的に不可能か」「何を言う義務があるか」を保証する。
> LLMは「何が怪しいか」「何を言うか」「誰に入れるか」「夜に何をするか」を決める。**

- 事実（CO・判定・投票・死亡・時系列）はコードが台帳から正確に出す。LLMに記憶させない。
- 論理（配役の定員、公開情報から確定すること、時系列の矛盾）はソルバーが出す。
  LLMに数えさせない。
- 不可能な出力（死者を吊る、公開した白を黒に反転、CO無しの結果公開）は検証で修正する。
  **「誰が人狼かを読み違える」は人間らしい誤りなので修正しない**（v2の方針を踏襲）。
- ソフトな推理と戦略（内訳、吊り順、囲い読み、CO時機、襲撃先）はLLMが人格と役職で決める。
- 発言と投票の一貫性は「上書き」ではなく、「自分が昼に推した相手」をモデルに見せ、
  変えるなら理由を言わせることで保つ。ずれは監査に残る（v2と同じ）。

## 4. v3 の構成（本PRで実装）

`WEREWOLF_REASONING_ENGINE=v3`。既定は v2 のまま（§6 の評価を通してから切り替える）。

| 層 | 担当 | 実装 |
|---|---|---|
| 事実 | コード | `PublicFactLedger`（既存） |
| 論理 | コード | z3 `RoleSolver`（既存）、`timeline.py`（既存） |
| 盤面の提示 | コード | **新規** `reasoning/board_memo.py`: 生存/死亡、CO一覧（共有の相互確認を含む）、判定一覧、投票表、公開情報だけで確定すること、時系列の矛盾、席だけが知ること。**名前のみ、IDなし** |
| 発言順・必須発言者 | コード | `select_opening_speakers` / `required_claim_speakers`（既存） |
| 公開義務（結果・CO） | コード | `DiscussionDecision.required_public_results`（既存）を「この発言で必ず言うこと」として渡す |
| 疑い・吊り先・投票・夜行動 | **LLM** | `DiscussionOutput.reasoning_memo.execution_target` を採用。`enforce_execution_target` は適用しない。投票・夜行動はモデル呼び出し |
| 発言 | **LLM** | チャット調のシステムプロンプト（`context.py` `_layer_a_chat`）、縮小した出力契約（`CHAT_DISCUSSION_OUTPUT_INSTRUCTION`）、人格ごとのチャット例文、17A用語ドクトリン（`knowledge/jinro-17a-chat-register.md`、v3限定） |
| 検証 | コード | `validate_discussion_output`（既存）。不正な対象は決定論的に修正 |
| 監査 | コード | 決定監査・投票変更分類（既存）。v3では `decision_target` = モデルの検証済み対象 |
| 狼チャット | **LLM** | 各狼が発言し、襲撃プロンプトに狼チャットの履歴が入る（分断の解消） |

LLMプロバイダには `LUNA_REASONING_EFFORT`（`low`/`medium`/`high`、空=送らない）を追加した。
エンドポイントが拒否した場合は1回の400で学習して以後送らない。推論トークンが
completion の7割を占める現状への、最初に回すべきつまみである。

## 6. 完成の定義と計測

「人間に見える」を測れる形にする。`scripts/evaluate.py` のレポートに次を追加した
（`app/eval/analyzers.py`）。

| 指標 | v2 ライブ実測 (gpt-5.6-luna, seed 11) | v3 の目標 |
|---|---|---|
| 定型句を含むAI発言率 | 98% | **0%** |
| 「(pN)」表記を含むAI発言率 | 100% | **0%** |
| 1日あたり公開発言数 | 約10 | **40以上**（最終的には人間の卓に近い80〜150） |
| 公開発言の平均文字数 | 150字超 | **30〜80字**（CO・整理のみ長い） |
| LLM呼び出し成功率 | 49% | **95%以上** |
| 公開発言1件あたりの待ち | 28秒 | **5秒以下**（§7 Phase C） |
| 人間判定 | 未計測 | 1日分のログを提示し、評価者が「AI/人間」を当てる正答率が **60%以下** |

加えて、推理の正しさについては既存のものを使う:

- 状態破損ゼロ（死者を対象にしない、白黒反転なし、投票履歴の誤認なし）: v2 と同じく 0 を維持
- 専門家カットオフ評価（v2版）の `plan utility` と `catastrophic avoidance`: v2 ブリーフを上回る
- 共有者の相互確認済みペアが「対抗」として語られない（回帰テスト追加済み）

**v3 を既定にする条件**: ライブ対戦2試合で上の指標を満たし、人間（開発者）が
トランスクリプトを読んで「かつての卓に近い」と判断すること。

## 7. 実装順序

### Phase A（本PR）

- v3 エンジン、盤面メモ、チャット調プロンプト、縮小出力契約、名前のみ表記、
  各狼の夜チャット、投票/夜行動のモデル決定、`LUNA_REASONING_EFFORT`、
  人間らしさ指標、共有者対抗バグ修正、テスト。

### Phase B（ライブ確認とドクトリン）: 1〜2週間

1. `WEREWOLF_REASONING_ENGINE=v3 LUNA_REASONING_EFFORT=low` で `scripts/evaluate.py --games 2`。
   成功率・途中切れ率・定型句率・発言数を確認。途中切れが残るなら出力契約をさらに削る
   （`public_results` と `directed_questions` 以外は任意にできる）。
2. 2本のケーススタディ（`docs/case_studies/`）の「再利用できる教訓」を
   `app/ai/knowledge/` のドクトリンに移す（v3限定・役職別）。
3. 人格ごとのチャット例文を実ログの口調に寄せる（権利上、原文は入れず特徴だけ）。
4. 専門家カットオフ評価を v3 のプロンプト（盤面メモ形式）で回し、v2 と比較。

### Phase C（体験の速度）: 1〜2週間

- 発言キューの並列生成: 次に話す予定の2〜3席の生成を同時に走らせ、ペーシング付きで
  順に表示する（`LUNA_MAX_CONCURRENCY` は既にある）。
- 1発言の長さを人格で短く、1日の発言数を増やす（`max_total`・`talkativeness` の再調整）。
- 人間の発言への即時反応: 名指しされた席と、直前の発言者だけを即座に生成する。
- UI: タイピング表示の複数同時化、短文の連投に合わせた表示密度。

### Phase D（人間判定）: 継続

- 1日分のログを提示して「どの発言がAIか」を当てる簡易テストを `scripts/` に追加。
- 判定結果を Phase B のドクトリン・例文に戻す。

### やらないこと

- RL の再開、実ログパーサー、重み学習。
- v2 ブリーフの改良。
- 人間の発言の高度な意味解析（v3 は人間の文章を**そのままログとして**LLMに読ませる。
  v2 の狭い正規表現による事実訂正はそのまま動く）。

## 8. リスクと対策

| リスク | 対策 |
|---|---|
| LLMが盤面メモにない事実を言う（幻覚） | メモに「メモにない判定・投票を作らない」と明記。発言から抽出した結果/COは既存の検証を通る。評価では `_check_contradictions` で検出 |
| 発言と投票のずれが増える | 投票プロンプトに「昼に推した吊り先」を提示し、変える場合は理由を要求。`vote_change` 監査で率を見る。v2 の 20% 台（宣言と投票の不一致率）を下回ることを確認する |
| 人狼の騙りが弱くなる | 役職/陣営の目的ドクトリン（既存）は v3 でも入る。騙りCO予定は必須発言者として保証（既存）。騙り結果は `public_results` で出す |
| 推論モデルの途中切れが続く | `LUNA_REASONING_EFFORT=low`、出力契約の縮小、`BriefDiscussionOutput` へのフォールバック（既存）。それでも残れば `max_completion_tokens` の学習上限を引き上げる |
| コストが上がる（投票・夜行動がモデル呼び出しに戻る） | 投票は1日16回、夜は3回。発言より桁が小さい。短い出力契約で相殺する。実測で `estimated_cost` を比較 |
