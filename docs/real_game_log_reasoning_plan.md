# 実ログを用いた推理高度化・データ基盤 実装方針

## この文書の位置づけ

この文書は、17人村の実ログを利用して `v2` 推理エンジンを高度化するときの設計契約である。
単なる調査メモではなく、今後の実装・データ取得・生成AIによる注釈・評価が守るべき境界を定める。

外部ログ取得、発言解析、可能世界、証拠重みづけ、投票評価に触れる作業を始める前に必ず読むこと。
既存の `docs/architecture.md` にある、公開事実・ハード制約・ソフト信念・陣営効用の分離を拡張する。

## 最終目標

推理を次の4段階に分離する。

1. **事実基盤**: その時点で観測可能だった出来事を正確に復元する。
2. **論理階層**: ゲームルールと明示した仮定だけから、可能世界と不可能世界を求める。
3. **重みづけ階層**: 論理的に残った世界のうち、発言・投票・CO・襲撃などから自然さを比較する。
4. **意思決定階層**: 役職推定と陣営目的を踏まえ、処刑・占い・護衛・襲撃の期待効用を比較する。

上位層の都合で下位層の事実や論理を曲げてはならない。
「起こりにくい」は重みづけであり、「不可能」ではない。

## 非交渉の設計原則

### 1. 事実・公開主張・真実を別に保存する

次の3つは別物である。

- `p1がp3を人狼だと思うと発言した`
- `p1が占い結果としてp3黒を公開した`
- `p3の真役職が人狼だった`

真占い師が公開した判定であっても、完全ログの能力実行システム行で裏付けられない限り、
真の占い実行結果として保存してはならない。結果騙り・結果入れ替えは論理上可能だからである。

### 2. 追加専用イベントを正本とする

原始発言、投票、処刑、死亡、能力実行、CO、訂正、撤回、スライドは、時系列のイベントとして保存する。
`current_claims` や `previous_votes` のような集約値はイベントから再構築する派生ビューであり、正本ではない。
派生ビューはイベント列との整合性を自動検証する。

### 3. 同じ事実の再掲は新しい事実ではない

能力結果の累積再掲を新規結果として数えてはならない。
少なくとも次のキーで同一性を管理する。

- claimant
- result type
- target
- source night / referenced day
- result value

再掲、訂正、撤回、置換は別イベントとして記録するが、元結果との関係を保持する。

### 4. 発言時点の情報だけを使う

各発言・各投票・各能力行動について、actorごとの情報スナップショットを作る。
終了後の役職、後日の霊結果、将来の死亡、狼会話を過去の判断入力へ混入させてはならない。

過去投票の評価も、後から確定した白黒を直接遡及適用しない。
「その時点で知り得た世界の中でどうだったか」を評価する。

### 5. プレイヤー視点の私的情報を再現する

公開盤面だけでは、AIの行動評価にならない。actorスナップショットには必要に応じて次を含める。

- 自分の役職
- 人狼仲間
- 共有相方
- 自分の能力実行と結果
- 自分が参加できた非公開会話
- 自分が知る護衛先・襲撃案

`TrueWorldPerspective` は評価・デバッグ専用とし、実プレイ推論へ入れない。

### 6. 人間の文章解析をハード制約に直結させない

生成AIや正規表現が抽出したCO・判定・内訳発言には、出典、確信度、代替解釈、レビュー状態を付ける。
第三者の役職への言及を自己COとして扱わない。
構造化出力があるAI発言はそれを正とし、自由文解析で別の自己COを追加しない。

### 7. 不完全取得を成功扱いしない

URLを見つけただけ、検索スニペットから一部を復元しただけ、投票表だけを取得しただけの状態を、
`parsed` や `paired` と表現しない。品質指標を分ける。

- URL pair identified
- raw HTML downloaded
- raw HTML hashed
- parsed from raw HTML
- public/full content aligned
- actor snapshots reconstructed
- training ready

## 論理階層: Possible World Solver

### 責務

論理階層は次だけを答える。

- この世界は成立可能か
- この事実・仮定の下で何が必ず成立するか
- ある前提はある結論を含意するか
- どの制約集合が矛盾したか
- 成立する代表世界、または必要なら世界集合は何か

確率、印象、定石、人間らしさをここへ入れない。

### 世界が表現すべきもの

現在の役職配置に加え、今後は必要に応じて次を明示的に表現できるようにする。

- 夜死亡の原因候補
- 未確定の夜行動対象
- COが真役職と一致するか
- 公開判定が事実と一致するか
- 公開判定が本物の能力実行由来か、捏造か
- 結果時系列の申告が正確か
- 結果をすべて開示したか
- 真役職の潜伏があるか
- 共有相方関係

ただし、役職配置、行動、公開主張、行動仮定を一つの概念に潰さない。
既存の `GenuineClaim`、`HonestResults`、`CompleteResultDisclosure`、
`NoLatentClaim`、`AccurateTimeline` の分離を維持する。

### 論理階層の出力

二階へ単一の疑いスコアを渡すのではなく、次を渡す。

- 可能世界
- 各世界の成立に必要な仮定
- 不可能理由 / unsat core
- 世界間の差分
- 条件付き確定
- 各役職・各陣営について世界を集約するための識別情報

## 重みづけ階層: 世界を評価する

### プレイヤーへ直接疑い点を足す方式から移行する

証拠は原則として人物へ直接加点せず、可能世界に対して
「この世界なら、この観測はどの程度自然か」を評価する因子として作用させる。

概念上は次の形とする。

```text
world_score = prior(world) + sum(evidence_factor(world, observation, context))
```

その後、狼を含む世界の重みを集約して人物別の役職評価を得る。
内部では数値を使ってよいが、UIや発言では根拠以上に精密な確率を提示せず、
既存の「本線 / 有力対抗 / 薄い / 論理上のみ / 不可能」を基本とする。

### 最初に実装する因子

1. 主張・時系列の整合性
2. CO時期と役職行動らしさ
3. 発言した処刑希望と実投票の関係
4. 投票変更と、その時点の票状況
5. 仲間擁護・仲間切り。ただし処刑可能性を条件にする
6. 確認済み関係や破綻後の推理更新

襲撃意図、意見噛み、護衛読み、狐確認などは、基礎データと条件付けが整ってから追加する。

### 二重計上を防ぐ

同じ作戦から派生した発言、黒判定、投票を独立証拠として無制限に足さない。
証拠には少なくとも次を持たせる。

- source event id
- causal group id
- speaker / actor
- target
- observation time
- information available at the time
- dependency / derived-from relation

同一因果群は最大値、飽和和、複合因子などでまとめる。

### 人格差

人格はハード制約を変更しない。
同じ世界集合に対し、どのソフト証拠を重く見るか、対抗世界をどこまで保持するか、
結論変更にどれだけ抵抗するかにだけ作用する。

---

## 意思決定階層

「もっとも狼らしい人物」と「今日処刑すべき人物」は別である。
次を分離する。

- 役職・陣営の評価
- 処刑した場合の情報価値
- PP/RPP、残り縄、狐処理
- 真役職候補を処刑する損失
- 占い、護衛、襲撃の陣営別期待効用

投票理由は、決定に使った世界・証拠・戦略目的から生成する。
議論後に結論が変わった場合は、内部だけで変更せず、再考理由を発言する機会を作る。

## 外部17Aログのデータモデル

### 推奨入力

標準17Aの役職非表示ログと終了後完全ログを同一ゲームで対にする。

- 非表示版: 各時点の公開情報再現
- 完全版: 真役職、能力実行、狼・共有会話、評価ラベル

完全版の秘密情報は入力特徴ではなくground truthまたは補助ラベル側へ隔離する。

### 原始イベントの最低フィールド

- game id
- event id
- source day と normalized discussion day
- phase
- sequence
- channel: public / wolf / freemason / monologue / graveyard / system
- speaker / actor / target
- raw text
- source HTML reference
- visibility
- parser version

### るる鯖固有の正規化

- 第一犠牲者を能動参加者と区別する
- 第一犠牲者への初回襲撃は戦略的襲撃学習に使わない
- るる鯖の「2日目」を、必要ならゲーム内の「議論1日目」と併記する
- 再投票ラウンドと票替えを保持する
- 共有・霊能スイッチを、CO、cover、slide、withdrawal、partner confirmation のライフサイクルで表現する

### actorスナップショット

各発言・投票・夜行動直前に、次を再構築できるようにする。

- available event ids
- alive players
- public claims and results
- confirmed relationships
- previous votes and current round votes
- actor private knowledge
- currently possible worlds または solver 入力
- actual action

イベント列を正本とし、集約フィールドは自動再構築・検証する。

## 生成AIによる注釈

生成AIに任せてよいもの:

- 発言の対象候補
- 主張、反論、質問、回答の分類
- 処刑希望、内訳仮説
- 根拠として参照した公開事実の候補
- 推理の前提候補
- 類似場面のクラスタリング
- 人間レビューが必要な難例の抽出

生成AIに最終確定させないもの:

- 投票、死亡、処刑、役職、能力実行
- 情報が公開された時点
- 同一結果の再掲判定
- 論理上の可能・不可能
- 専門家の世界順位

全注釈に model、prompt version、confidence、alternatives、review status を残す。
不明は無理に一つへ決めない。

---

## 専門家データの作り方

人間専門家には絶対的な加点値より、次の形式で判断を求める。

1. **論理問題**: 可能、不可能、条件付き確定を回答する。
2. **世界間比較**: AとBのどちらが自然か、差は弱いか強いかを回答する。
3. **反実仮想**: 一要素だけ変え、評価がどちらへ動くか回答する。
4. **行動比較**: 同じ信念状態から、どの行動が陣営効用上よいかを回答する。

自然文の一事例をそのままルール化しない。
事実、仮定、論理帰結、ソフト因子へ分解し、反例を作り、両方を通ってから実装する。

## テスト方針

### 事実基盤

- 同一結果の再掲でイベント上の元結果数が増えない
- 第三者役職言及が自己COにならない
- 公開版と完全版の公開発言列が一致する
- 完全情報が公開スナップショットへ漏れない
- actor固有の私的情報だけが入る
- 派生ビューがイベント列と一致する

### 論理階層

- 可能世界集合
- 不可能内訳とunsat core
- 条件付き確定
- 名前を入れ替えた同型盤面で同じ結果
- 無関係イベント追加で世界集合が変わらない
- 同一事実の再掲で世界集合が変わらない

### 重みづけ階層

正確な小数より順位と方向をテストする。

- 世界Aが世界Bより上
- 特定証拠を足すと指定方向へ動く
- 無関係な発言で順位が動かない
- 同じ証拠の再掲で重みが増えない
- 同一因果群の二重計上がない
- 後知恵で過去投票を評価しない
- 確認済み共有への黒が、共有本人ではなく判定者の真世界を下げる

### 意思決定

- 役職評価と処刑効用が分離される
- PP/RPPと狐生存を考慮する
- 結論変更時に説明可能な理由がある

## 2026-08 るる鯖パイロットから得た教訓

外部生成AIが作成した試作ZIPは、スキーマ骨格としては有用だったが、元HTML取得に失敗し、
検索インデックス等から部分復元したものだった。104イベント中、公開発言は8件、投票は73件で、
発言・推理・夜会話を用いた学習には使用できない。

残すべき点:

- raw / parsed / schema / review の分離
- 原始イベント、主張、スナップショット、ground truth の分離
- JSON Schemaと品質フラグ
- 不完全性を明記する姿勢

修正必須点:

- 元HTML未取得なのに paired / parsed と数えない
- 真占いの公開結果を能力実行のground truthへ昇格させない
- actor private knowledgeを空にしない
- previous_votes等の派生ビューをイベント列と一致させる
- 役職スイッチの開始・解除・相方確認をライフサイクルで保存する
- 第一犠牲者、日数、初回ランダム襲撃を正規化する

最初の合格単位は10試合ではなく、**1試合を端から端まで完全に通すこと**である。

### 1試合のtraining-ready合格条件

1. 公開版と完全版の実HTMLを取得し、URLとhashを保存する
2. 全公開発言を抽出する
3. 公開版と完全版の公開発言を対応づける
4. 全投票、再投票、処刑、死亡を抽出する
5. 能力実行は完全ログのシステム行から取得する
6. 狼、共有、独り言、霊界を別channelにする
7. CO、訂正、撤回、スライド、相方確認を再現する
8. 各行動時点のactor別知識を再現する
9. ground truthを推論入力から隔離する
10. parser errorとambiguous annotationを隠さず保存する

このゲートを通るまで、試合数の拡大、重み学習、行動頻度の統計化を行わない。

## 実装順序

### Phase 0: 現行推理の状態破損を修正

- 能力結果再掲の冪等性
- 自己CO抽出の主語制約
- 確認済み共有関係
- 判定者が破綻・狼確定した後の信頼更新
- 発言した処刑先と投票先の不一致説明
- 投票評価の後知恵排除

### Phase 1: 1試合完全パーサー

標準17Aを1試合だけ選び、training-readyゲートを通す。
取得不能時に検索スニペットで穴埋めして成功扱いしない。

### Phase 2: Possible World拡張

世界、行動仮定、主張の真偽、結果時系列、潜伏、夜死亡原因を比較可能な形へ拡張する。

### Phase 3: 専門家シナリオ

論理問題、世界比較、反実仮想を50〜100問作り、回帰テストとして固定する。

### Phase 4: 世界重みづけ

最初は主張整合性、CO時期、投票変更、確認関係、仲間への態度に限定する。
人物への単純加点から、世界単位の因子評価へ段階移行する。

### Phase 5: 大規模化

通常村、上級村、名勝負、失敗例、年代を分けて標本化する。
同一プレイヤー、同一村、同一時代のリークを避けてtrain/evalを分割する。
権利、利用規約、アクセス頻度、生ログ再配布可否を確認する。

## 次の生成AIが着手するときのチェックリスト

- この変更は事実、論理、重み、効用のどの階層か
- 「不自然」を「不可能」にしていないか
- 後から知った情報を過去へ漏らしていないか
- 同じ証拠を二重計上していないか
- actor固有の視点を再現しているか
- イベント列と派生ビューのどちらが正本か明確か
- 実ログがtraining-readyゲートを通っているか
- 生成AI注釈を確定事実として扱っていないか
- 反例と同型盤面テストを追加したか
- 変更理由を次のAIがコードとテストから追えるか
