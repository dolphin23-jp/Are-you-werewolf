# アーキテクチャ / 設計思想

## 背景

本プロジェクトは、過去に作られた人狼AIプレイヤー実装(Claude Haiku ベース)の
「理念」を抽出し、LLMプロバイダを **gpt-5.6-luna**(OpenAI互換API)に差し替えた
上で、コードは一から新規に設計・実装したものです。

引き継いだ設計思想:

- **エンジン/AI分離**: `backend/app/engine/` はLLMを一切知らない、純粋で
  決定的なゲームルール実装。人間もAIも同じ `GameController` API
  (`chat`/`vote`/`submit_night_action`/`co` 等)を呼ぶ。
- **5層プロンプト構成**(`backend/app/ai/context.py`):
  [A] 人格 / [B] 役職情報 / [C] 盤面分析(ロープ計算など) / [D] 過去日要約
  (ローリング圧縮) / [E] 当日全文ログ。
- **人格システム**(`backend/app/ai/personalities.py`): 口調×思考スタイル×
  議論スタイル×感情傾向の4軸から成る15プリセット。
- **2層の戦略ガイド**(`backend/app/ai/strategy.py`): コード計算(ロープ数・
  グレーリスト・CO構成)+ 静的ドクトリン文。
- **欺瞞パターン事前コミット**(`backend/app/ai/deception.py`): 人狼陣営は
  ゲーム開始時に欺瞞パターン(偽占い/偽霊媒/全潜伏など)を確率的に決定し、
  `FakeClaimGuard` で嘘の一貫性を検証する。
- **COは公開文と構造化公開宣言の一致で確定**(`backend/app/ai/coordinator.py`):
  `public_claim_role` だけの隠しCOは認めず、公開文から同じ役職COを確認できた場合だけ登録する。
- **フェーズ別並行性ポリシー**: 議論=有限多段階、投票=並列、夜=依存関係あり。
  議論前に非公開の朝発言意思を並列生成し、結果発表・朝一COを先行させる。その後、全員の
  初期見解、直接質問、主要処刑候補の反論、再評価を優先度付きキューで処理する。1人3回
  (主要候補4回)、総発言数は生存者数の2.5倍までのため必ず停止する。夜は占い/護衛/内輪
  チャットを並列実行し、人狼の襲撃決定はそれらを踏まえて後段で行う。
- **モックLLMファースト**(`backend/app/ai/provider/mock.py`): テストと
  `scripts/dry_run.py` はネットワーク費用ゼロで完結する。

新たに追加した基盤:

- **公開事実台帳**(`backend/app/ai/reasoning/`): AI側が「事実」として扱って
  よい唯一の投影。`facts.PublicFactLedger` は `GameState` を参照するだけの
  読み取り専用ビューで、`co_declarations` / `public_result_claims` /
  `vote_records` などの可変コピーは作らない(スナップショットを持つと、
  翌朝に死亡者が処刑候補へ戻るような乖離が起きる)。真の役職・真の死因・
  他人の非公開能力結果はこの境界を越えない。

## 公開発言イベント

CO・判定・撤回・スライド・訂正は、追記専用の `SpeechEvent`
(`backend/app/engine/speech_events.py`)として記録する。平坦な
`list[CoDeclaration]` では答えられない問いがあるためである。

- 誰が、どの発言(message_id)で言ったのか
- 占いCOは撤回されたのか、共有へスライドしたのか
- この判定は元の主張か、訂正後か
- そもそも「CO」だったのか、曖昧な人間の文をマッチャが推測しただけか

`co_declarations` / `public_result_claims` / `freemason_partner_claims` は、
このログから導出される**互換ビュー**であり保存領域ではない。書き込み経路は
`GameController.record_speech_event` 一箇所で、`co()` / `public_result()` /
`claim_freemason_partner()` はその薄いラッパーである。

**確信度**が、曖昧な人間の文を確定COへ昇格させない仕組みである。
`CLAIM_CONFIDENCE_THRESHOLD` 未満のイベントも記録はする(「CO風の何かが言われた」
という事実自体が証拠になる)が、いかなる導出もそれを盤面のCO構成へ入れない。

AI側は逆向きである。構造化出力(`public_claim_role` / `public_results`)は
**宣言**であり、正規表現が本文中に同じ内容を見つけられたかどうかに登録を依存させない。
代わりに本文の方を合わせる — `ensure_fact_sentences` が、宣言された事実を述べていない
公開文へ定型の事実文を書き込むので、可視テキストと台帳が食い違わない。
自由文の解析は、構造化出力が空だったカテゴリの穴埋めと、人間の発言にのみ使う。

## 推理基盤の分離

推理は3つの独立した層に分けている。

1. **事実**(`reasoning/facts.py`): 公開情報だけを投影する。
2. **整合性検証**(`reasoning/validation.py`): AI出力のうち「あり得ないもの」
   だけを拒否・修正する。死亡者を処刑候補にする、未処刑者へ霊媒結果を出す、
   公開済みの白判定を黒へ反転させる、といった状態破損が対象で、「誰が人狼か
   を読み違える」ことは人間らしい誤りなので触らない。修正は必ず決定的で、
   本人の前回の結論→本人の suspects→席順の先頭、という順に解決する
   (ランダムな代替を選ぶと、説明のつかない投票が残る)。
3. **決定的要約**(`reasoning/summaries.py`): 日次要約の公開事実部分は
   LLMではなくコードで生成し、生成された講評は別見出しへ隔離する。

各規則は小さなモジュールに分かれており、後続の推理機能が単一の巨大ファイルへ
集中しないようにしている。宣言した処刑先と実際の投票先の食い違いは
`VotePlanMismatch` として**記録するだけ**で修正しない — 心変わりは正当なプレイで、
それを取り違えないのは読み手の仕事だからである。

## 視点と役職制約ソルバー

`backend/app/ai/reasoning/solver/` は、17人固定配役に対して「その配置はあり得るか」
「その役職は確定か」「その仮定はその結論を導くか」をLLMなしで答える。人狼プレイヤーが
常に考えていて、言語モデルが最も不得意な種類の問いである。

### 視点が唯一のゲート

規則モジュールは `ObservationSet.true_roles` を直接読まない。`Perspective` に
「何を知っているか」を尋ね、視点が答える。これが、村側の推論が実際の配役に
こっそり依存することを防ぐ唯一の仕組みである。

| 視点 | 知っていること |
|---|---|
| `CommonPublicPerspective` | 何も(公開ルールのみ) |
| `GenericVillagerPerspective(self_id)` | その席が村人だと仮定 |
| `PlayerPrivatePerspective(player_id)` | 配られたカード。人狼は仲間、共有者は相方 |
| `TrueWorldPerspective` | 全部。**テスト・評価・デバッグ専用** |

狂人は人狼陣営だが**人狼の位置を知らない**。妖狐も自分以外を知らない。どちらも
視点が ally を返さないことで実現しており、規則側に例外は要らない。
`TrueWorldPerspective` は `perspective_for()` から到達できず、`debug_only` フラグと
`require_in_game()` で実プレイ経路に入り込めば例外になる。

### 層の分離

`backend.py` が契約と宣言的な制約IR、`z3_backend.py` だけが z3 を知る、
`rules/` が推論規則1つにつき1モジュール、`queries.py` がキャッシュ付きファサード、
`explanations.py` がコード由来の理由。後で weighted model counting などへ差し替えても、
規則には一行も触れずに済む。

**決定性**を速度より優先している。`is_possible` 等は本来決定的だが、モデル列挙は
そうではない — どの充足世界を先に見つけるかはソルバーの実装詳細であり、実行ごとに
「代表世界」が入れ替わるAIはデバッグできない。そのため列挙は席順を固定し、各席を
可能な最小の役職へ順に固定することで、毎回辞書順最小の世界を返す。列挙数には上限がある。

### 主張と騙り物語(PR5)

公開COと公開判定は**観測事実**として取り込むだけで、ハード制約にはしない。
世界に効くのは呼び出し側が明示した**行動仮定**だけである。

| 仮定 | 意味 |
|---|---|
| `GenuineClaim(p, role)` | pは本当にその役職 |
| `HonestResults(p)` | pが公開した判定は事実として正しい（役職の真偽とは独立） |
| `CompleteResultDisclosure(p)` | 結果を隠していない（件数が夜数と合う） |
| `NoLatentClaim(role)` | その役職の潜伏者はいない |

`GenuineClaim` と `HonestResults` を分けているのは、「狂人の偽黒が偶然本物の人狼に
刺さった世界」が普通に成立するからである。これを1つにまとめると、その世界が
表現できなくなる。`NoLatentClaim` が「単独占いCOは確定か」のトグルであり、
**単独COだから真、というルールはどこにも無い**。

`ClaimedStoryPerspective(actor_id, claimed_role)` は騙り手の公開用内訳。騙る役職
だけを既知とし、本人の真のカードと仲間は入れない。同じプレイヤーの
`PlayerPrivatePerspective` とは別インスタンス・別IDなので、キャッシュも混ざらない。

矛盾は **unsat core** で返す。全制約の羅列ではなく実際に衝突している部分集合
（「占い師はちょうど1人 / p3のCOを真と仮定 / p7のCOを真と仮定」）を、宣言した
モジュール自身の文言で返す。説明をLLMに作らせない。

`Certainty` は「不可能・可能・確定・条件付き確定」を区別する。4つ目が実戦では重要で、
「この占いが真ならXは狼」は知識でも憶測でもない。

### 夜イベント(PR6)

このルールセットで夜に死ぬ経路は2つしかない — 人狼の襲撃1件と、占われた妖狐の呪殺1件。
以下はすべてその帰結であり、**どちらだったか分かる視点でのみ**成立する。

卓には区別がつかない。朝の死体は襲撃死か呪殺死で、公開死因はその2つを意図的に潰す。
そのため公開モジュールはほとんど何も導かず、夜行動を取った席は多くを導く。
これが「夜の推理が視点によって異なる」ということで、そうでなければ村は
人狼の情報でプレイしていることになる。

| モジュール | 必要な視点 | 導けること |
|---|---|---|
| `DeathRuleModule` | 公開 | 同じ夜に死体が2体 → **どちらかが妖狐**（襲撃1・呪殺1しかないため） |
| `AttackRuleModule` | 人狼 | 自分の襲撃先でない夜の死体 → 呪殺 → **妖狐** |
| `GuardRuleModule` | 狩人 | 護衛したのに死んだ → 襲撃は防いだので呪殺 → **妖狐** |
| `FoxCurseRuleModule` | 占い師 | 占って生き残った → **妖狐ではない**。占っていない夜の死体も**妖狐ではない** |

夜の死体が1体だけなら公開視点では何も確定しない。死体なしも同様で、護衛成功と
妖狐噛みの両方が説明として残る。

**「噛まれた占いCO者は真か狂人」はハード制約にしない。** 良いプレイではあるが論理ではない。
同様に、村役職の騙りを禁止するルールは無いので、非狼・非狐の役職騙りを論理上除外しない。

`RuleModule` は `extract_soft_evidence` を持つが、このPRでは全モジュールが空を返す。
襲撃尤度をここで決め打ちすると、信念エンジンができる前に推測が基盤へ焼き込まれる。

### z3 依存の理由

17席×8役職の固定枚数配分に、席ごとの私的知識が乗る問題は素直な制約充足であり、
SMTソルバーは「可能・確定・含意」を厳密に答える。手書きの列挙は遅いうえに、
微妙に間違えやすい。依存は `z3_backend.py` 一箇所に閉じている。

## 信念エンジン(PR7)

`backend/app/ai/reasoning/belief/` は、各AIが**独立した**疑い・信頼・有力内訳を持ち、
事実訂正で根拠が崩れたら正しく再計算できるようにする。同じ証拠から17人が同じ結論に
達するなら、それは17個の帽子をかぶった1人のプレイヤーである。

### 由来のない疑いは撤回できない

疑い度のあらゆる変化は、名前のある `EvidenceRecord` へ紐づく。撤回すれば必ずスコアが動く
ので、**「投票先を勘違いしていたのは認める。でも同じ理由でやはり怪しい」は表現できない**。
証拠は削除せず `active=False` にする — 撤回された論拠が残ること自体が監査記録になる。

再計算は差分ではなく**総入れ替え**。差分更新は撤回済みの論拠の亡霊をスコアへ残しうる。

### 硬い結論と柔らかい証拠

ソルバーの判定は**硬い**。ルールが除外した席は除外されたままで、重み付けも性格(PR8)も
説得力のある主張も、それを並べ替えられない。それ以外はすべて重み付きのソフト証拠である。

### 事実訂正は台帳に照合する

「私はダイキには投票していない、ユイへ投票した」は記録についての主張であり、記録が答えられる。
コードで照合し、**モデルに「この人は正直か」を尋ねない**。確認できた訂正は、誤った事実に
乗っていた証拠を撤回し、指摘した人の信頼を上げる。反証された訂正は信頼を下げる。
確認できないものはどちらもしない。

投票証拠のソースIDには**投票先が含まれる**（`vote:p0:1:1:p12`）。これが、誤った引用と
正しい引用を区別可能にし、訂正が「まさにその読み違い」だけを撤回できる理由である。

## 認知性格と騙りの二面性(PR8)

### 性格は口調ではなく重みに効く

口調だけの違いは人格ではない。言い回しが違うだけで同じ投票をする2人は、2つの声を持つ
1人のプレイヤーであり、それが並ぶ卓は台本に見える。そこで `CognitiveTraits`(9軸)は
**各証拠カテゴリの重み**に効かせる。

**硬い線**: 性格が触れるのはソフト証拠だけ。ソルバーが確定させた席は、頑固な players にも
同調型にも動かせない。性格は「何を説得的と感じるか」を決めるのであって、「何が真か」ではない。

- 同調型は `majority_pressure` を強く受ける。懐疑型は `conformity - contrarianism` で
  ほぼ受けないが、**負にはならない** — 「みんながXと言うからXは偽」は符号を反転した同調に過ぎない
- 頑固さは乗り換えコスト（`switching_cost`）になる
- 証拠重視型は事実訂正での振れ幅が大きくなる
- 反権威・反対型は `minority_review_band` が広く、少数仮説を真剣な検討対象に残す

### 仮説ランクは言葉で返す

**本線 / 有力対抗 / 薄い / 論理上のみ / 不可能** の5段階。パーセンテージは出さない。
盤面のどこにも「73.4%」を正当化する根拠はなく、小数第一位まで書くことは推論が持っていない
権威を捏造する。最下段も重要で、「論理上あり得るが誰も論じていない」は実在する状態である。

### 騙り手は二つの頭を持つ

盤面を推理する人狼と、偽占いを弁護する人狼は、別の情報から別の問いに答えている。
混ぜると両方向に壊れる — 物語が人狼陣営しか知らない事実に寄りかかり始め、
人狼が自分の作り話を信じ始める。

`DeceptionState` は `private_perspective`（本当の席）と `public_story`
（騙る役職だけを既知とする）を同時に持つ。狂人も同じ構造で、私的視点は自分のカードだけ
— 人狼の位置を知らないことがその役職の形そのものであり、偽黒が偶然本物に刺さる理由でもある。

物語が UNSAT になったら `StoryStatus.COLLAPSED` へ移り、制約IDと説明を持つ。
**身内切りは禁止しない** — 論理上は常に可能で、`betrayal_cost` という戦略上の価格が付くだけ。

## 推理基盤の実ゲーム統合(PR9)

`WEREWOLF_REASONING_ENGINE=legacy|v2` で切り替える。**既定は legacy** — 切り替えは
意図的な行為であるべきで、アップグレードの副作用であってはならない。

### LLMを使わずコード化したもの

投票 / 夜行動 / 朝の発言タイミング / 発言者選定 / 日次要約 / 事実訂正照合 /
内輪会話のチーム計画。

投票は信念状態上の argmax である。モデルに再導出させても、リクエストと
「誰も監査できない答え」が増えるだけだった。モデルに残るのは、モデルが実際に得意な部分
— それを人格に沿って言うこと — である。

### 計測結果（mock、seed 11/12/13、同一の人間スタブ）

| 指標 | legacy | v2 |
|---|---|---|
| 論理LLM要求数 | 731 | **293 (-60%)** |
| 死亡者への行動対象指定 | 0 | **0** |
| 公開事実の白黒反転 | 0 | **0** |
| 実投票履歴の誤認 | 0 | **0** |
| 第一処刑候補の集中度(平均) | 0.479 | 0.455 |
| 独立意見の分散 | 計測不可 | 0.546 |

集中度が上がらなかったのは、証拠が並んだときの**同点処理を席番号順にしない**ようにした
ためである。序盤はほとんどの灰が同じ（ゼロ）証拠を持つので、席番号で割ると全員が同じ名前を
挙げてしまう — 合意に見えるが、実際はソートの副作用である。根拠が無いときにどの灰を疑うかは
本当に任意なので、席ごとにシード付きで変える。あくまで**第二キー**で、証拠が分けた候補は動かせない。

### z3 のカーディナリティ符号化

配役枚数は基数制約なので `Sum(If(...))` ではなく `PbEq` を使う。算術形はこの盤面で
**約40倍遅く**、それは「使えるターン」と「目に見える待ち」の差だった。

## 陣営別の意思決定と私的能力結果(PR10)

### 「知っている」と「そうしたい」は別物

人狼を人狼だと知っていることと、その人物を処刑したいことは、村人にとっては同じで
人狼にとっては正反対である。これを1つの「疑い度」へ潰すと、ソルバーが正しく私的に
「仲間は人狼だ」と教えた瞬間、村向けの効用関数がそれを「処刑せよ」と読む。
**実際、v2の人狼は初日から仲間を第一投票候補にしていた。**

`PlayerBeliefState` は4つを分離する。

| フィールド | 意味 |
|---|---|
| `private_role_certainties` | 自分のカード・自分の能力結果・ソルバーが確定させたもの |
| `public_suspicion_scores` | 卓で主張できること。ソフト証拠のみ、性格が効くのはここだけ |
| `execution_utility_scores` | **陣営別**の処刑選好 |
| `attack_/guard_/divine_utility_scores` | 夜行動ごとに独立した選好 |

`utility.py` が陣営ごとの効用を持つ。人狼は仲間へ `ALLY_PROTECTION` の負値を置くので、
**身内切りは禁止ではなく価格付き** — 圧倒的な公開圧があれば選ばれる。
狂人は疑い度を反転して「卓が信用している席」を押し、妖狐は自分への圧を下げつつ両陣営を削る。

### 私的能力結果

`PrivateDivineResult` / `PrivateMediumResult` を観測へ追加し、取得は必ず `Perspective` 経由。
`OwnAbilityResultRuleModule` が本人の結果をハード制約にするので、真占い師は**公開前から**
自分の黒を確定として扱える。

**白は村人確定ではない。** 「人狼ではない」だけで、妖狐も狂人も白を出す。
白を村確定として符号化するのは、ここで可能な最も破壊的な誤りである。

### 夜行動は疑い度の流用をやめる

占いは既占い対象を除外し情報価値で選ぶ。護衛は「最も白い席」ではなく失えない役職を守る。
襲撃は疑い度を使わない — 疑い度は村の通貨であり、それを流用すると人狼は
**自分たちの最良の隠れ蓑を噛んでしまう**。

## 発言・信念・人間入力の統合(PR11)

### 結論は言葉より先に決まる

推論システムが2つ並走していた。投票はランタイムが決め、議論の中身はモデルの
自由記述メモが決める。両者は当然ずれるので、AIが一日中ある名前を推してから
別の名前へ投票できてしまった。

`reasoning/dialogue.py` の `DiscussionDecision` がこれを閉じる。発言が生成される
**前**に信念エンジンから組み立てられ、`render_brief()` が結論・根拠・確度帯を
固定文言でプロンプトへ差し込む。モデルに委ねるのは口調・長さ・説明の順序・
誰に質問するかだけで、末尾にそう明記する。生成後は `_speak` が
`reasoning_memo.execution_target` を決定値で上書きするので、
**モデルが指示を無視しても結論は動かない**(テストでは常に `p16` を返す
`DisobedientProvider` で確認している)。

投票時の整合性チェックは、内部の別の数値ではなく
`stated_target` — その席が実際に卓へ言ったこと — と突き合わせる。
内部値どうしの比較はランタイムが自分の答案を自分で採点しているに等しい。
ずれた場合は握り潰さず `vote_change` として理由付きで記録する。

`vote_decision` のタイブレークソルトは `current_execution_target` と同一
(`f"{player_id}:execution"`)。別のソルトを使うと、評価が完全に並んだ候補間で
発言と投票がタイブレークだけの理由で分岐し、誰もしていない心変わりに見える。

### 人間の一文は一度だけ構造化する

`parse_argument()` が人間のメッセージを1回、コード上で `ArgumentEvent` に変換する。
16席それぞれにモデルで読ませれば、同じ一文に対する少しずつ違う16通りの解釈を
得るために16リクエストを払うことになる。

- **事実の訂正**は全席に同一に適用される。記録は記録である。
- **戦略的主張**(「占い師を残せ」「便乗しているだけだ」)は助言であって事実ではない。
  ソフト証拠として入り、各席の `source_trust` と性格特性が重みを変える。
  だから同じ一文で卓が割れる — 合唱ではなく卓になる。

正規表現は意図的に狭い。取りこぼした文はただの雑談になるが、これは安全な失敗であり、
曖昧な不満から告発をでっち上げる方は安全ではない。

### 朝は「言うことがある席」から始まる

`_coded_discussion_round` は全員に発言させない。信念は全席分更新されるが、
16人が順に所見を述べる朝は誰も読まないテキストの壁になる。
未公開結果の保持・CO予定・名指し質問を持つ席は**義務発言者**として順序の先頭に固定され、
価値ランキングに落とされることはない。残りは答えられたか反論されたときに話す。

訂正で根拠を失った席は `queue_reassessment_speakers` で発言キューに積まれる。
訂正が通ったのに誰も何も言わないのは、卓としておかしい。

## 時系列と、事実が消えたときの根拠(PR12)

### 判定は「色」ではなく「いつ・誰を・どの能力で」

公開判定は色と公開日しか持っていなかった。占い師が1日目夜の黒を3日目まで
伏せてから出すのは普通のプレイだが、公開日から夜を逆算していたため
「2日目夜に見た」と読まれる。`ClaimedStoryPerspective` が偽占いの日程を
再構成するのにこの逆算を使っていたので、騙り本人が卓へ話していない日程で
死体照合をしていた。

`referenced_day` を `SpeechEvent` から `PublicResultClaim` → `PublicResultFact`
→ `PublicVerdict` まで通し、`source_night` が「未指定なら公開日の前夜」という
既定を1か所に持つ。

### 公開カレンダーとの矛盾は硬い事実ではない

`reasoning/timeline.py` が公開情報だけで矛盾を検出する — 同じ夜に2件の占い、
まだ来ていない夜、既に埋葬された対象、処刑のない日の霊媒結果、処刑者と違う
霊媒対象、自分の死亡後の夜。

**これらは硬い制約にしない。** 真占い師が夜を言い間違えることも、伏せていた
結果を守るため時系列だけ嘘をつくこともある。よって出口は2つだけ:

- 信念エンジンのソフト証拠(疑うのは**申告者**であって名指しされた側ではない)
- `AccurateTimeline(p)` 仮定 — 「pの申告した時系列は正確だ」と**明示的に**
  仮定した呼び出し元にだけ制約を返す

検出は意図的に保守的。占い師が襲撃された夜の占いは、外から見れば同時刻なので
矛盾として報告しない。存在しない矛盾を作る方が、見逃すより悪い。

### 根拠は、その事実が消えたら消える

公開黒が根拠を作り、申告者が後で撤回・訂正しても、根拠は残っていた。
席は卓の記録から消えた判定を引用し続ける — 誤った投票履歴を保持し続けるのと
同じ種類の失敗である。

`EvidenceOrigin` が「どの公開事実の上に立っているか」を持つ。
`source_event_ids` が「どのメッセージから来たか」を答えるのに対し、
こちらは「それは今もあるか」を答える。撤回された判定はメッセージIDを永久に
持ち続けるので、後者の問いだけが消滅に気づける。

`synchronise_public_facts` が毎回の観測前に走り、生きている公開事実の集合に
無いものを非活性化する(削除ではない — 撤回された議論の監査証跡が残る)。
色は事実IDの一部なので、黒→白の訂正は「同じ事実の値が変わった」ではなく
「別の事実になった」として扱われる。
CO争いも同様に、争っている全員の集合が事実IDになる。占いCOが2人いてその片方が
撤回すれば争いは消え、残った側の「争点CO」根拠も一緒に消える。

### 判定の重みは申告者の信用で伸縮する

同じ黒でも、以前に矛盾を指摘された申告者のものは軽い。ただし
`MIN_RESULT_TRUST_FACTOR` で下限を持ち、**符号は決して反転しない** —
「お前を信じない」は「お前の言った逆が正しい」の証拠ではない。

### 騙りの公開物語が本番に繋がった

`claimed_roles` を本番の誰も渡していなかったため、`ClaimedStoryPerspective` は
テストの中にしか存在しなかった。占い騙りの人狼は自分の本当のカードを見ながら
騙りを考えていたことになる。`refresh` が各席の**自分の**カードと**自分の**COを
比べて騙りを検出する(他人については何も分からないので漏洩はない)。

### 撤回・スライド・訂正を入力から作れる

`ClaimAction` / `ResultAction` を `DiscussionOutput` に追加。宣言フィールドから
`ROLE_RETRACTION` / `ROLE_SWITCH` / `RESULT_RETRACTION` / `RESULT_CORRECTION` を
生成し、`ensure_fact_sentences` が公開文にも正規文言を入れる。
人間には狭い正規表現の経路があるが、**撤回するものが実際に立っているときだけ**
発火する。「間違っていたかもしれません」はためらいであって撤回ではない。

宣言された訂正は色の変更が目的なので極性チェックを通す一方、
`ABILITY_RESULT` の黙った反転は従来どおり拒否する。

## LLMプロバイダ

`backend/app/ai/provider/base.py` の `LLMProvider` プロトコルを介して
プロバイダを抽象化。実装は2つ:

- `mock.py`: 決定的・シード可能なテスト用ダブル。
- `luna_openai.py`: `openai.AsyncOpenAI` を使った gpt-5.6-luna 実装。
  strict JSON-schema structured output を第一経路とし、失敗時は
  `json_object` モード + 寛容パーサー(生パース→フェンス付きJSON抽出→
  最初の`{`〜最後の`}`)にフォールバックする。

`WEREWOLF_LLM_PROVIDER` 環境変数で明示的に切り替える(`mock` | `luna`)。
`luna` 選択時に `LUNA_API_KEY` が未設定なら起動時に即エラーとする
(旧実装のAPIキー文字列を見て自動フォールバックする挙動はやめた)。

## 旧実装から修正した既知の問題

| 旧実装の問題 | 対応 |
|---|---|
| 同期SDKを`async def`内でブロッキング呼び出し | `AsyncOpenAI`を徹底使用 |
| プレーンテキスト+正規表現JSONパースのみ | structured output を第一経路に |
| 単一グローバルインメモリセッション | `SessionStore`で複数ゲーム対応 |
| プロバイダ抽象化なし | `LLMProvider`プロトコル+2実装+factory |
| 投票/夜フェーズでのLLM呼び出しが無制限並列 | `LUNA_MAX_CONCURRENCY`セマフォ |
| APIキー文字列の中身で自動モック判定 | `WEREWOLF_LLM_PROVIDER`明示指定 |

## セッション管理

`backend/app/sessions/store.py` の `SessionStore` インターフェースにより、
複数ゲームを同時に扱える(v1はインメモリ実装。永続化が必要になれば
同インターフェースの別実装に差し替え可能)。

## API / 通信

REST(セッションスコープ) + WebSocket(リアルタイムpush、`GameEvent`を
JSON化してブロードキャスト) + ポーリングfallback。AIターンの
オーケストレーションは `backend/app/api/orchestrator.py` に集約され、
人間の行動(チャット/投票/夜行動)をトリガーに `AICoordinator` を呼ぶ。
